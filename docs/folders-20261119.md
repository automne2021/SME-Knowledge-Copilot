## Hành vi đã triển khai

- Admin dùng `PATCH /api/v1/documents/{id}` với JSON bắt buộc có `folder_id` UUID hoặc null để gán/chuyển/bỏ phân loại. Gán lại cùng thư mục được phép; response 200 trả metadata hiện tại, gồm `folder_id`. Thiếu identity → 401; member ghi → 403; tài nguyên ngoài workspace/không tồn tại → 404; document trong workspace đang `deleting`/`deleted` với đích hợp lệ → 410 `source_unavailable`. Field thiếu, sai UUID/kiểu, hoặc ngoài contract → 422.
- Upload nhận một field `folder_id` UUID tùy chọn bên cạnh đúng một `file`. Bỏ field để chưa phân loại; chuỗi rỗng hoặc `null` dạng text không phải UUID. Field lặp, file thừa hoặc field không được phép đều bị từ chối; giữ giới hạn tổng request, bytes file và dọn file khi đăng ký SQL thất bại. Scope folder được kiểm tra cả ở service để bảo vệ caller ngoài API.
- Gán folder trong cùng transaction document/revision/job; chỉ trả upload 202 sau commit. Giữ nguyên response ba trường `document_id`, `job_id`, `status`. Dedup vẫn theo hash/workspace, không theo folder: upload trùng sang thư mục khác trả 409 và giữ nguyên phân loại của tài liệu đã có.
- Mọi thành viên dùng `GET /api/v1/documents?folder_id=<UUID>`. SQL lọc trước sắp xếp/limit; folder hợp lệ rỗng trả `{items:[]}`; ID không tồn tại/ngoài workspace trả 404; UUID sai/rỗng trả 422. Không gửi filter thì giữ danh sách toàn workspace. Như danh sách hiện hữu, vẫn liệt kê `deleting`, loại `deleted`; list/detail/PATCH trả `folder_id`.
- Chỉ sửa metadata SQL, không tạo job/revision, đổi lifecycle/generation, thay vector payload hay reindex. Không thay schema/dependency/model/prompt/config, không migrate DB development, không triển khai search/chat folder scope hoặc UI.

## Lựa chọn và đánh đổi

- **SQL là nguồn phân loại:** dùng FK `documents.folder_id` đã có và lọc SQL; tránh lưu tên/folder trong vector payload, vì mỗi lần chuyển thư mục sẽ cần đồng bộ Qdrant hoặc reindex. Việc chọn folder cho search/chat và trace/idempotency thuộc T3, không suy ra từ list filter.
- **Khóa khi gán:** giữ `FOR KEY SHARE` ở folder đích trước `FOR UPDATE` trên document tới commit. Key-share chặn xóa folder, phối hợp với `delete_folder` T1, nhưng cho phép nhiều lần gán cùng folder. Khóa folder `FOR UPDATE` cho mọi lần gán sẽ tuần tự hóa không cần thiết; chỉ kiểm tra tồn tại rồi update không khóa có race với delete. Xem lại nếu thêm bulk move, cây thư mục hoặc quyền riêng theo folder.
- **Lifecycle:** khóa document và `populate_existing=True` để ORM đọc lại trạng thái đã commit từ transaction khác; object cache cũ không được quyết định rằng nguồn vẫn khả dụng. Các test riêng kiểm tra cache cũ, writer đang giữ khóa và chuyển sang `deleting`.
- **Upload:** kiểm tra folder sau khi stream được lưu, bên trong đường đăng ký/dọn file có sẵn, nên caller trực tiếp cũng được kiểm tra và lỗi scope không để orphan. Đổi lại request sai folder vẫn có thể ghi file tạm trước khi bị từ chối; giới hạn upload vẫn áp dụng. Có thể thêm precheck sớm để giảm I/O nếu có số đo cho thấy cần, nhưng vẫn phải revalidate khi đăng ký.
- **Chưa phân loại:** PATCH dùng JSON null; multipart upload bỏ field. List T2 chỉ nhận một UUID, chưa thêm bộ lọc riêng cho tài liệu chưa phân loại hoặc thay đổi phân trang hiện hữu (code đang limit mặc định 50, tối đa 100).
